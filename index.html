Operating principles运行原则

Trust comes from restraint.

Visual Feedback Studio does not pretend a browser click is a safe code edit. It preserves the separation: browser captures intent, receiver stores facts, the agent changes source only when the mapping is reliable.Visual Feedback Studio 不会把浏览器点击伪装成安全代码修改。它保持分层：浏览器捕捉意图，receiver 存储事实，agent 只在映射可靠时修改源码。

01

Collect, never overwrite只采集，不覆盖

The extension records visual review data. It never writes into your project directly.插件只记录视觉审稿数据，从不直接写入你的项目。

02

Keep concerns separate保持职责分离

Extension, receiver, and agent remain separate layers with narrow responsibilities.插件、receiver 与 agent 保持三层解耦，每层只做自己的事。

03

Apply only when reliable可靠才落地

Copy can auto-apply on unique matches. Style and notes require source-aware reasoning.文案唯一匹配时可自动应用；样式与备注需要结合源码结构判断。

04

Never guess blindly不强行猜改

Low-confidence feedback stays visible for human review instead of becoming a risky patch.低置信度反馈保留给人工判断，不会冒险生成补丁。

Why it exists为什么需要它

Last mile of visual review.

Design has comments. Code has pull requests.设计稿有评论，代码有 PR。

The broken part is the running page: seeing what feels wrong, adjusting it in context, and getting that intent back into source without screenshots, vague chat messages, or manual transcription.断掉的是跑起来的页面：看到哪里不对，在真实上下文里调整，然后把意图回到源码，而不是截图、群聊描述、手动整理。

Ship the review loop接入审稿闭环

Open browser. Ship source.

Clone the public repo once, then run setup from the project root you want to review. It installs the skill, starts the receiver, prints the extension path, and keeps the browser permission model store-safe.先克隆一次公开仓，再在你要审稿的项目根目录运行 setup。它会安装 skill、启动 receiver、输出扩展路径，并保持浏览器权限模型适合商店分发。
